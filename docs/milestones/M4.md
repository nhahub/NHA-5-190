# M4 - Personalization, context, and wardrobe optimization

**Window:** October 11-17, 2026

**Status:** Planned contract; personalization, optimization outputs and integration
acceptance are not verified in this repository.

## Goal

Rerank M3 candidates using preferences and context, then quantify wardrobe gaps and candidate-item utility.

| Owner | Deliverable |
|---|---|
| Eyad | Feedback events and preference-profile representation |
| Hayat | Configurable `FinalScore = alpha*OCS + beta*Preference + gamma*Context` |
| Ziad | Weather/temperature, season, occasion, and formality signals |
| Omar | Wardrobe gap analysis through simulated additions |
| Hana | WUS components: gain, AvgOCS, preference, context, redundancy |
| Asmaa | M3-to-M4 integration and product-matching-ready output |

Marketplace integration is outside scope; M4 produces a versioned output contract for a future application layer.

## Input contract

- Accepted M3 candidates/ranks with item IDs, original OCS, and model/config versions.
- Versioned preference profiles and feedback events, wardrobe membership, and
  context inputs with source/time and missing-value policy.
- Agreed score scales, alpha/beta/gamma configuration and WUS component definitions.
  Live weather/API access is not assumed; context acquisition is the owner's decision.

## Output contract

- Reranked outfits retaining original M3 score/rank and exposing preference,
  context, final score, new rank and producing profile/configuration versions.
- Gap/addition simulations linked to the baseline wardrobe and candidate item;
  report gain, AvgOCS, preference, context and redundancy components with WUS.
- Product-matching-ready structured records with item IDs and explanations, without
  marketplace integration. Document units, component scales, aggregation, weights,
  missing-feedback/context behavior and deterministic tie handling.

## Acceptance

- Exact rerank/simulate commands load accepted M3 artifacts and preserve traceability.
- Component scores and approved formulas permit recomputation of each final result;
  no missing signal is silently fabricated.
- Owners report generic-versus-personalized comparisons and weight/context sensitivity
  using documented scenarios; synthetic scenarios are explicitly identified.
- Asmaa reviews the integrated outputs for M5 with the [handoff packet](../HANDOFFS.md).
  Weight choices, WUS normalization and quality thresholds remain owner decisions.
