## Input and output contract

Inputs are the raw manifest, source files acquired separately, per-dataset
annotations and official split metadata. The existing manifest contains only
the locally inspected inventory, including Fashionpedia and Polyvore validation
data; training readiness must not be inferred from it.

Owner-produced outputs must include preprocessing/loader configuration, garment
records with source image and annotation links, saved project splits with original
split identity, and a documented taxonomy/missing-label policy. Each derived item
retains stable IDs, source release, original reference, producing configuration,
and traceability to its parent image. An image row and a garment row are different
units; document that relationship rather than silently replacing IDs.

Downstream review requires each owner's runnable acceptance command, counts and
exclusions, corruption/annotation findings, split/leakage evidence, and the
[handoff review packet](../HANDOFFS.md). Existing repository/sample checks are
research infrastructure checks; they do not complete these pending team outputs.
