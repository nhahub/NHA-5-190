# M2 - Clothing understanding and representation

**Window:** September 27-October 3, 2026

**Status:** Eyad's LAB color component and Ziad's attribute target/mask construction
are implemented and tested on available samples. Attribute model training remains
blocked by the missing Fashionpedia training release. Other model components,
final representation integration and the full feature cache are not verified.
Scheduled dates do not establish completion. See [the color handoff](../m2/color_extraction.md)
and [the provisional attribute handoff](../m2/attributes.md).

## Goal

Freeze a versioned item representation containing category, supported attributes and mask, garment-region colors, and embeddings.

| Owner | Deliverable |
|---|---|
| Eyad | Garment-aware LAB color extraction and final Polyvore feature cache |
| Hayat | CLIP experiments and embeddings |
| Ziad | Supported attributes and explicit missing-attribute mask |
| Omar | Model comparison and recommendation |
| Hana | Initial taxonomy/schema and final representation integration |
| Asmaa | ResNet baseline, fine-tuning and evaluation |

These assignments match the [Notion-reconciled ownership table](../team/OWNERSHIP.md).

M3 starts after the representation schema/cache version is frozen. Conditional experiments cannot delay the core representation.

## Input contract

- Accepted M1 loader, preprocessing and garment outputs with stable IDs, source
  references, saved splits, taxonomy, and explicit annotation availability.
- Approved training/evaluation populations and raw-access instructions; validation
  samples alone do not constitute a training release.

## Output contract

- Versioned item records following the [representation draft](../architecture/system-overview.md):
  item ID, category/score, attributes and availability mask, garment-region LAB
  palette, embedding reference, and source/split provenance.
- Cache inventory linking every record to its feature file; document embedding
  dimension/dtype/model version, palette shape/weights, attribute ordering, score
  semantics, missing values and excluded/failed items.
- ResNet baseline, CLIP comparison and attribute/color findings with producing
  configurations, checkpoint/cache acquisition and evaluation scope. Generated
  weights and feature caches remain outside Git.

## Acceptance

- Owners supply exact build/load commands and schemas; each cache reference resolves
  and IDs match the accepted M1 population or documented exclusions.
- Missing attributes remain masked; unapproved cross-dataset label mapping is absent.
- Model comparisons use documented splits and metric definitions, with no test-set
  tuning claim disguised as evaluation.
- Omar, Hana and Asmaa approve the schema/cache version and can load it for M3.
  Exact shapes, score ranges, metrics and quality thresholds require owner decisions.
  Submit the [handoff packet](../HANDOFFS.md); the color component alone does not
  complete the full representation/cache contract.
